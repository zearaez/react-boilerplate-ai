# Conventions

Most of these are enforced by ESLint. The ones that are not are marked, and are
candidates for a rule.

## Naming

| Thing               | Form                           | Example                                  |
| ------------------- | ------------------------------ | ---------------------------------------- |
| Files               | kebab-case                     | `post-detail-page.tsx`                   |
| Components          | PascalCase, named export       | `export function PostCard()`             |
| Mobile route files  | kebab-case, **default export** | `app/(app)/posts/new.tsx`                |
| Hooks               | `useThing`                     | `usePostsQuery`                          |
| Query-key factories | `<name>Keys`                   | `postKeys`                               |
| zod schemas         | `<name>Schema`                 | `createPostInputSchema`                  |
| Types from schemas  | `z.infer`, never hand-written  | `type Post = z.infer<typeof postSchema>` |
| Booleans            | `is`/`has`/`can` prefix        | `isPending`, `hasNextPage`               |
| Env vars            | `VITE_*` / `EXPO_PUBLIC_*`     | `VITE_API_URL`                           |

Web pages are `*-page.tsx` and export a named component; the router imports it.
Mobile screens are whatever the route path needs and export default, because
expo-router requires it.

## Imports

Ordered, with a blank line between groups — autofixed by `pnpm lint:fix`:

```
react → react-native → expo-* → other external → @repo/* → @/ or ~/ → relative → types
```

`@/` is the alias inside `apps/web`; `~/` is the alias inside `apps/mobile`. Both
mean "this app's root". Shared code is always `@repo/*`.

## File size

There is no lint rule for this, deliberately — a hard cap invites splitting a file
in a way that makes it harder to read. The working guide is ~250 lines for a
component and ~400 for a logic module. If a screen is longer, the usual cause is
business logic that belongs in a `@repo/core` hook.

## Comments

Explain **why**, not what. The bar: would a reader be tempted to "simplify" this
into a bug? Then say why it is the way it is. Most comments in this repo point at an
upstream issue, a failure mode, or a decision that looks wrong until explained.

Do not leave commented-out code. Git remembers.

## What goes where

`packages/core` is platform-agnostic logic and contains no JSX. `packages/tokens`
is the only place a colour is defined. `packages/mocks` is a fake backend and
imports nothing from `@repo/core`. Apps own their own UI.

The full table is in [AGENTS.md](../AGENTS.md), and
[architecture/monorepo-graph.md](architecture/monorepo-graph.md) has the diagram —
which must stay byte-consistent with the `no-restricted-imports` config, or people
will trust the diagram over the linter and lose.

## Generated files — never edit

| File                                   | Generated by       |
| -------------------------------------- | ------------------ |
| `apps/web/src/global.css`              | `pnpm tokens:sync` |
| `apps/mobile/global.css`               | `pnpm tokens:sync` |
| `apps/web/public/mockServiceWorker.js` | `msw init`         |
| `pnpm-lock.yaml`                       | pnpm               |

Each carries a DO-NOT-EDIT header, and a drift test fails CI if `global.css` and
`tokens.ts` disagree.
